# Техническое задание
## Интегрируемый модуль онлайн-чата для сайтов с CRM-функционалом

---

## 1. Введение

### 1.1 Цель проекта
Разработка SaaS-решения для организации онлайн-поддержки клиентов через веб-виджет с интеграцией Telegram, системой управления заявками и аналитикой работы менеджеров.

### 1.2 Назначение системы
Система предназначена для:
- Предоставления онлайн-консультаций посетителям сайтов
- Централизованного управления обращениями из разных источников (виджет, Telegram)
- Организации работы команды менеджеров
- Аналитики качества обслуживания клиентов

### 1.3 Область применения
- Интернет-магазины
- Сервисные компании
- Консультационные службы
- Любые веб-сайты, требующие онлайн-поддержки

---

## 2. Описание системы

### 2.1 Общая архитектура
Система состоит из следующих компонентов:

1. **Веб-виджет** — интегрируемый JavaScript-модуль для встраивания на сайты клиентов
2. **Административная панель** — веб-интерфейс для управления системой
3. **Telegram-бот** — единый бот для всех сайтов владельца с автоопределением источника
4. **Backend API** — серверная часть на Django
5. **Frontend** — клиентская часть на Next.js
6. **База данных** — PostgreSQL
7. **Real-time коммуникации** — WebSocket для мгновенного обмена сообщениями

### 2.2 Основные возможности
- Встраиваемый чат-виджет с настраиваемым дизайном
- Интеграция с Telegram для продолжения диалогов
- Канбан-доска для управления заявками
- Автоматическое распределение обращений по очереди менеджеров
- Система быстрых ответов и автоответов
- Статистика и аналитика работы
- Оценка качества обслуживания клиентами

### 3.3 Модуль веб-виджета

#### 3.3.1 Внешний вид и поведение
- Минимизированная кнопка чата (иконка с индикатором непрочитанных)
- Развернутое окно чата (минимум 300x400px)
- Адаптивность под мобильные устройства
- Кастомизация цветов согласно настройкам

#### 3.3.2 Форма начала диалога
**Обязательные поля:**
- Telegram никнейм (обязательно)

**Опциональные поля:**
- Имя клиента
- Email
- Начальное сообщение

#### 3.3.3 Функционал чата в виджете
- Отправка текстовых сообщений
- Прикрепление файлов (изображения: JPG, PNG; документы: PDF, DOCX; макс. 10 МБ)
- Отображение истории переписки (для вернувшихся посетителей по cookie/localStorage)
- Индикатор "менеджер печатает"
- Отображение времени отправки сообщений

#### 3.3.4 Переход в Telegram
- После указания Telegram никнейма виджет переходит в режим "read-only"
- Отображение истории переписки
- Кнопка "Продолжить в Telegram" с deep-link на бота
- Все последующие сообщения идут через Telegram

### 3.4 Модуль Telegram-интеграции

#### 3.4.1 Архитектура бота
- Единый бот для всех сайтов владельца
- Автоопределение сайта через реферальные параметры в ссылке
- Возможность ручного выбора сайта, если клиент написал напрямую

#### 3.4.2 Сценарии взаимодействия

**Сценарий 1: Клиент начал в виджете**
1. Клиент указывает TG никнейм в виджете
2. Виджет переходит в режим просмотра
3. Клиент переходит по ссылке в Telegram
4. Бот автоматически связывает диалог с заявкой
5. Вся дальнейшая переписка идет в Telegram

**Сценарий 2: Клиент перешел по ссылке с сайта**
1. На сайте размещена уникальная реферальная ссылка на бота
2. Клиент переходит по ссылке
3. Бот автоматически определяет сайт по параметру
4. Создается новая заявка, привязанная к сайту

**Сценарий 3: Клиент нашел бота самостоятельно**
1. Клиент пишет боту напрямую
2. Бот предлагает выбрать сайт из списка (кнопки)
3. После выбора создается заявка

#### 3.4.3 Функционал в Telegram
- Отправка/получение текстовых сообщений
- Отправка/получение файлов
- Синхронизация с панелью менеджера в реальном времени
- Отправка сообщения с просьбой оценить обслуживание при закрытии заявки

### 3.5 Модуль административной панели

#### 3.5.1 Dashboard (главная страница)
- Общая статистика по всем сайтам

- Количество новых заявок за сегодня
- Средняя оценка обслуживания
- Быстрый доступ к канбан-доске

#### 3.5.2 Канбан-доска управления заявками

**Структура доски:**
- **Колонка "Новые"** — нераспределенные заявки
- **Колонка "В обработке"** — заявки, взятые в работу менеджерами
- **Колонка "Общались ранее"** — заявки для объединения лидов (видны всем)
- **Колонка "Закрытые"** — завершенные заявки
- Возможность создания динамических колонок (настраивается админом)

**Карточка заявки содержит:**
- Имя клиента
- Название сайта
- Ответственный менеджер (или "Не назначен")
- Время последней активности
- Индикатор непрочитанных сообщений
- Канал общения (виджет/Telegram)

**Функционал доски:**
- Перетаскивание карточек между колонками (Drag & Drop)
- Фильтрация по сайтам
- Фильтрация по менеджерам
- Поиск по имени клиента, тексту сообщений
- Сортировка по дате создания, последней активности

**Видимость заявок:**
- **Менеджер** видит: свои заявки + нераспределенные + колонку "Общались ранее"
- **РОП** видит: все заявки
- **Админ** видит: все заявки

#### 3.5.3 Интерфейс чата для менеджера

**Основной функционал:**
- Список активных диалогов (левая панель)
- Окно переписки (центральная часть)
- Информация о клиенте (правая панель)

**Левая панель — список диалогов:**
- Фильтр: "Мои диалоги" / "Все диалоги" / "Нераспределенные"
- Поиск по имени клиента
- Индикация непрочитанных сообщений
- Последнее сообщение и время

**Центральная часть — окно чата:**
- История переписки с прокруткой
- Поле ввода сообщения
- Кнопки быстрых ответов (персональные шаблоны менеджера)
- Кнопка прикрепления файлов
- Индикатор "клиент печатает"
- Кнопка "Закрыть заявку"

**Правая панель — информация:**
- Имя клиента
- Telegram никнейм (если указан)
- Сайт, с которого обращение
- Канал общения (виджет/Telegram)
- Время создания заявки
- Время последней активности
- История статусов заявки

**Быстрые ответы:**
- Кнопки с шаблонами сообщений над полем ввода
- Настройка личных шаблонов в профиле менеджера
- Горячие клавиши для вставки шаблонов

**Отправка файлов:**
- Поддержка форматов: JPG, PNG, PDF, DOCX
- Максимальный размер: 10 МБ
- Хранение на сервере

#### 3.5.4 Объединение лидов
- Доступно всем менеджерам в колонке "Общались ранее"
- Функция "Объединить с заявкой"
- Выбор целевой заявки из списка
- Слияние истории переписки
- Сохранение всех данных клиента

### 3.6 Модуль распределения заявок

#### 3.6.1 Настройка очереди (Админ)
- Создание списка менеджеров в порядке очереди
- Drag & Drop для изменения порядка
- Включение/исключение менеджеров из очереди

#### 3.6.2 Настройка таймингов (Админ)

**Для онлайн-менеджеров:**
- Время ожидания первого ответа (по умолчанию: 5 минут)
- При превышении — автоматическое переназначение следующему в очереди

**For оффлайн-менеджеров:**
- Время ожидания для оффлайн-менеджера (по умолчанию: 2 минуты)
- При превышении — заявка переходит к следующему онлайн-менеджеру
- Цель: не задерживать клиента, но дать возможность менеджеру ответить

#### 3.6.3 Логика распределения

**При поступлении новой заявки:**
1. Заявка попадает в колонку "Новые"
2. Система находит первого менеджера в очереди со статусом "Онлайн"
3. Назначает заявку этому менеджеру
4. Отправляет уведомление менеджеру
5. Запускает таймер ожидания ответа

**Если менеджер онлайн не ответил за X минут:**
1. Отправка уведомления РОПу
2. Автоматическое переназначение следующему в очереди
3. Фиксация в статистике (пропущенная заявка)

**Если менеджер оффлайн:**
1. Заявка назначается, но с другим таймингом
2. Если не ответил за Y минут — переход к следующему онлайн
3. Фиксация в статистике

**Цикличность очереди:**
- После последнего менеджера в списке очередь начинается с первого

#### 3.6.4 Ручное управление заявками
- Админ/РОП может переназначить заявку вручную
- Менеджер может взять нераспределенную заявку самостоятельно
- При взятии заявки она автоматически назначается менеджеру

### 3.7 Модуль уведомлений

#### 3.7.1 Уведомления менеджерам

**В веб-интерфейсе:**
- Звуковое уведомление при новой заявке
- Звуковое уведомление при новом сообщении в назначенном чате
- Визуальный индикатор непрочитанных сообщений
- Desktop-уведомления (с разрешения браузера)

**В Telegram (опционально для команды):**
- Можно настроить отдельный бот для уведомлений команде
- Уведомления о новых заявках
- Напоминания о неотвеченных сообщениях

#### 3.7.2 Уведомления РОПу
- При неответе менеджера в течение 5 минут
- Ежедневная сводка по работе команды (опционально)

#### 3.7.3 Уведомления клиентам
- Автоответ вне рабочих часов
- Сообщение с просьбой оценить обслуживание при закрытии заявки

### 3.8 Модуль статусов менеджеров

#### 3.8.1 Статусы
- **Онлайн** — менеджер активен в системе
- **Отошел** — временное отсутствие (устанавливается вручную)
- **Оффлайн** — менеджер не в системе

#### 3.8.2 Автоматическое определение
- Онлайн — активность в течение последних 5 минут
- Отошел — устанавливается менеджером вручную
- Оффлайн — отсутствие активности более 10 минут или выход из системы

#### 3.8.3 Влияние на распределение
- Онлайн-менеджеры получают заявки по очереди с коротким таймингом
- Менеджеры "Отошел" пропускаются в очереди
- Оффлайн-менеджеры получают заявки с увеличенным таймингом

#### 3.8.4 Учет в статистике
- Общее время в каждом статусе за период
- Процентное соотношение статусов
- Отображение в профиле менеджера и общей статистике

### 3.9 Модуль оценки качества

#### 3.9.1 Запрос оценки
- Отправляется клиенту при переводе заявки в статус "Закрыто"
- Через Telegram (если диалог в TG) или виджет (если в виджете)
- Текст сообщения настраивается админом для каждого сайта

#### 3.9.2 Шкала оценки
- 5-балльная шкала (звезды)
- Опциональное текстовое поле для комментария

#### 3.9.3 Привязка оценки
- Оценка привязывается к менеджеру, который закрыл заявку
- Сохраняется в профиле менеджера
- Учитывается в общей статистике

#### 3.9.4 Отображение
- Средняя оценка менеджера в его профиле
- Список всех оценок с комментариями
- Сводка в общей статистике

### 3.10 Модуль статистики и аналитики

#### 3.10.1 Доступ
- **Админ** — полный доступ ко всей статистике
- **РОП** — полный доступ ко всей статистике

#### 3.10.2 Общая статистика (для Админа/РОПа)

**Метрики по обращениям:**
- Общее количество обращений (всего, за период)
- Распределение по сайтам

**Метрики по времени:**

**Метрики по менеджерам:**
- Количество обработанных заявок на менеджера
- Количество заявок в работе
- Средняя оценка по менеджерам
- Время в статусах (онлайн/оффлайн/отошел)
- Количество пропущенных заявок

**Метрики качества:**
- Распределение оценок (5★, 4★, 3★, 2★, 1★)
- Средняя оценка по системе
- Средняя оценка по сайтам
- Динамика оценок по периодам

**Графики:**
- Динамика обращений (день/неделя/месяц)
- Распределение по часам суток
- Воронка обработки заявок

#### 3.10.3 Личная статистика менеджера
- Количество обработанных заявок
- Средняя оценка
- Среднее время ответа
- Количество активных заявок
- Личная динамика за период

#### 3.10.4 Фильтры и период
- Выбор периода: сегодня, вчера, неделя, месяц, произвольный
- Фильтрация по сайтам
- Фильтрация по менеджерам

## 4. Роли и права доступа

### 4.1 Владелец аккаунта (Админ)

**Управление:**
- Полный доступ к настройкам всех сайтов

- Настройка виджетов и ботов
- Настройка очереди распределения заявок
- Настройка таймингов и автоответов
- Управление общими шаблонами ответов

**Работа с заявками:**
- Просмотр всех заявок
- Работа с чатами (как менеджер)
- Переназначение заявок
- Объединение лидов
- Закрытие заявок

**Статистика:**
- Полный доступ ко всей статистике
- Экспорт данных

**Настройки:**
- Настройка личных быстрых ответов
- Настройка уведомлений
- Управление профилем

- Просмотр настроек сайтов (без редактирования)

**Работа с заявками:**
- Просмотр всех заявок
- Работа с чатами (как менеджер)
- Переназначение заявок
- Объединение лидов
- Закрытие заявок

## 5. Бизнес-процессы и сценарии использования

### 5.1 Сценарий: Обращение через виджет с переходом в Telegram

1. Клиент заходит на сайт
2. Открывает виджет чата
3. Заполняет форму: указывает Telegram никнейм
4. Отправляет первое сообщение
5. Система создает заявку, назначает менеджеру по очереди
6. Виджет переходит в режим "read-only" с кнопкой "Продолжить в Telegram"
7. Клиент переходит по ссылке в Telegram
8. Telegram-бот автоматически связывает диалог с заявкой
9. Менеджер получает уведомление в панели
10. Менеджер отвечает в панели → сообщение приходит клиенту в Telegram
11. Клиент отвечает в Telegram → сообщение появляется в панели менеджера
12. После решения вопроса менеджер закрывает заявку
13. Клиент получает сообщение с просьбой оценить обслуживание
14. Клиент ставит оценку → она сохраняется в профиле менеджера

### 5.2 Сценарий: Обращение напрямую в Telegram

1. Клиент переходит по реферальной ссылке с сайта или находит бота самостоятельно
2. Пишет сообщение боту
3. Бот определяет сайт (по реферальному параметру или предлагает выбрать)
4. Система создает заявку, назначает менеджеру
5. Менеджер отвечает → переписка идет в Telegram
6. После решения вопроса менеджер закрывает заявку
7. Клиент получает запрос на оценку

### 5.3 Сценарий: Автоматическое переназначение при неответе

1. Новая заявка назначена Менеджеру 1 (онлайн)
2. Менеджер 1 не отвечает в течение 5 минут
3. Система отправляет уведомление РОПу
4. Заявка автоматически переназначается Менеджеру 2 (следующему в очереди)
5. Менеджер 2 получает уведомление
6. В статистике фиксируется пропущенная заявка для Менеджера 1

### 5.4 Сценарий: Распределение при оффлайн-менеджере

1. Новая заявка должна быть назначена Менеджеру 1 (оффлайн)
2. Заявка назначается Менеджеру 1 с увеличенным таймингом (например, 2 минуты)
3. Менеджер 1 не отвечает за 2 минуты
4. Заявка переназначается следующему онлайн-менеджеру в очереди
5. В статистике фиксируется время оффлайн для Менеджера 1

### 5.5 Сценарий: Объединение лидов

1. Клиент "Иван" написал в виджет на сайте → создана Заявка #1
2. Позже "Иван" написал напрямую в Telegram-бота → создана Заявка #2
3. Менеджер замечает, что это один и тот же клиент
4. Менеджер переносит Заявку #2 в колонку "Общались ранее"
5. Использует функцию "Объединить с заявкой"
6. Выбирает Заявку #1
7. История обеих заявок объединяется в одну
8. Заявка #2 удаляется, Заявка #1 содержит всю историю

### 5.6 Сценарий: Работа вне рабочих часов

1. Клиент открывает виджет в 23:00 (вне рабочих часов)
2. Вместо формы чата видит сообщение: "Мы сейчас не работаем. Наш график: 9:00-18:00. Напишите свой вопрос, и мы ответим завтра."
3. Клиент может написать сообщение
4. Заявка создается, но остается в статусе "Новые" до начала рабочего дня
5. В начале рабочего дня заявка автоматически входит в очередь распределения

#### Frontend:

- **Язык:** TypeScript
- **Стилизация:** Tailwind CSS
- **WebSocket клиент:** Socket.io-client
- **Управление состоянием:** React Context API / Zustand

#### Виджет:
- **Vanilla JavaScript** (без зависимостей для минимального размера)
- **WebSocket** для real-time коммуникации
- **CSS** с инлайн-стилями для изоляции

#### Инфраструктура:
- **Контейнеризация:** Docker, Docker Compose
- **Веб-сервер:** Nginx
- **WSGI-сервер:** Gunicorn
- **Развертывание:** Возможность деплоя на VPS/облако

### 6.2 Архитектура базы данных

#### Основные таблицы:

**Users (Пользователи):**
- id, email, password_hash, role (admin/rop/manager), created_at, is_active

**Sites (Сайты):**
- id, owner_id (FK Users), name, url, widget_settings (JSON), telegram_settings (JSON), working_hours (JSON), created_at

**Chats (Заявки/Чаты):**
- id, site_id (FK Sites), client_name, telegram_username, assigned_manager_id (FK Users), status, channel (widget/telegram), created_at, updated_at, closed_at

**Messages (Сообщения):**
- id, chat_id (FK Chats), sender_type (client/manager), sender_id (FK Users, nullable), content, file_url, timestamp

**Ratings (Оценки):**
- id, chat_id (FK Chats), manager_id (FK Users), rating (1-5), comment, created_at

**Templates (Шаблоны ответов):**
- id, user_id (FK Users, nullable - если NULL, то общий шаблон), title, content, hotkey, created_at

**Queue (Очередь менеджеров):**
- id, owner_id (FK Users), manager_id (FK Users), position, is_active

**ManagerStatuses (Статусы менеджеров):**
- id, manager_id (FK Users), status (online/away/offline), changed_at

**Files (Файлы):**
- id, message_id (FK Messages), filename, file_path, file_size, mime_type, uploaded_at

### 6.3 API Endpoints (примерные)

#### Авторизация:
- POST `/api/auth/register` — регистрация
- POST `/api/auth/login` — вход
- POST `/api/auth/logout` — выход
- POST `/api/auth/reset-password` — сброс пароля

#### Сайты:
- GET `/api/sites` — список сайтов
- POST `/api/sites` — создание сайта
- GET `/api/sites/{id}` — информация о сайте
- PUT `/api/sites/{id}` — обновление настроек
- DELETE `/api/sites/{id}` — удаление сайта

#### Заявки:
- GET `/api/chats` — список заявок (с фильтрами)
- POST `/api/chats` — создание заявки
- GET `/api/chats/{id}` — детали заявки
- PUT `/api/chats/{id}/assign` — назначение менеджера
- PUT `/api/chats/{id}/status` — изменение статуса
- POST `/api/chats/{id}/merge` — объединение заявок

#### Сообщения:
- GET `/api/chats/{id}/messages` — история сообщений
- POST `/api/chats/{id}/messages` — отправка сообщения
- POST `/api/messages/upload` — загрузка файла

#### Пользователи:
- GET `/api/users` — список пользователей
- POST `/api/users` — создание пользователя
- PUT `/api/users/{id}` — обновление пользователя
- DELETE `/api/users/{id}` — удаление пользователя

#### Статистика:
- GET `/api/stats/overview` — общая статистика
- GET `/api/stats/managers` — статистика по менеджерам
- GET `/api/stats/ratings` — статистика оценок

#### Шаблоны:
- GET `/api/templates` — список шаблонов
- POST `/api/templates` — создание шаблона
- PUT `/api/templates/{id}` — обновление
- DELETE `/api/templates/{id}` — удаление

#### WebSocket:
- `/ws/chat/{chat_id}` — real-time сообщения в чате
- `/ws/notifications/{user_id}` — real-time уведомления менеджеру

### 6.4 Интеграция с Telegram

#### Технологии:
- Библиотека: `python-telegram-bot`
- Webhook или Long Polling

#### Функционал бота:
- Обработка команды `/start` с параметрами
